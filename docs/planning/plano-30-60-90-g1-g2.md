## 0.1 Regra de parada — cloud como único bloqueio (27/11/2026)

Quando todo o trabalho de engenharia necessário para a publicação estiver concluído, com evidência e sem P0/P1 de engenharia aberto, e o único bloqueio restante for o ambiente cloud, a engenharia para: não abre PRs, features, refactors ou setup cloud/billing/loja; deixa a `main` verde e sem WIP; produz um handoff com pronto, evidências, o que falta de cloud, comandos/runbook, riscos e rollback; reporta ao CEO e aguarda autorização explícita antes de qualquer ação cloud. O mesmo vale se as únicas pendências forem do owner (D07/textos legais, device físico, Play Console). Em dúvida, perguntar ao CEO. Ver ADR 0026.

**Estado em 27/11:** o G1 local de engenharia está concluído e o T08 completo. O único item de engenharia restante é o reparo das crianças acima do módulo 1 sem entitlement ativo (ADR 0025). Depois dele, o gatilho é atingido e o time congela; G2/G3 não começam.

## 2. Regras do ciclo

1. Não expandir escopo. Conteúdo e features novas ficam congelados até G1/G2.
2. Uma PR por comportamento, com CI obrigatória e evidência sem PII.
3. `main` protegida: PR, checks `Flutter app`, `Cloud Functions` e `Security Rules`, squash merge.
4. Billing continua desabilitado até produto aprovado, verificação server-side e sandbox completos.
5. Nada de produção. Ambiente de trabalho agora: emulador Android + Firebase Emulator Suite. Cloud fica pausado até o gate de retomada.
6. ADR obrigatório para auth, pagamento, entitlement e dados infantis.
7. Evidência local é rotulada como local; configuração externa ou teste físico só contam como concluídos com evidência anexada.
8. Quando o cloud for retomado, o deploy manual em dev pode usar o login local do Firebase CLI; credenciais nunca vão para o repositório ou para o CI. Produção continua proibida.
9. Quando o cloud for o único bloqueio para a publicação, parar e aguardar autorização explícita do CEO; não iniciar G2/G3 nem inventar trabalho (ADR 0026).

## 5. Riscos

| Risco | Impacto | Mitigação |
| --- | --- | --- |
| Cloud pausado | Nada pode ser declarado em ambiente real | Evidência local rotulada; deploy/App Check/físico ficam como gate posterior (ADR 0021) |
| Divergência de portas/stack local | App e Functions apontam para emuladores diferentes (8080/8081) | Uma stack canônica por rodada ou porta documentada; não commitar override local de porta |
| Evidência local tratada como produção | Falso positivo de G1 | Rotular `local`; não fechar G2/G3 sem cloud e device físico |
| App Check mal configurado | Chamadas de dev negadas ou enforcement contornado | Debug token documentado, teste de negação e ativação gradual |
| Migração `primary` com perda de dados | Corrupção de perfis infantis | Dry-run, contagens, export, rollback e ensaio em staging |
| Billing sem produto aprovado | G3 não fecha e há risco de cobrança incorreta | Compra desabilitada, feature flag e sandbox obrigatório |
| Escopo novo no meio do ciclo | Atraso de G1/G2 | Congelamento até o gate; exceção só com aprovação do CEO |
| Uma única conta GitHub | Sem revisão independente | CI obrigatória, evidência e gate formal do CEO |
| Sem device físico | Evidência física fica para o gate posterior | Registrar bloqueio; não substituir teste físico por emulador |
| Atalho Android-only quebra a portabilidade | Retrabalho quando o iOS voltar | ADR 0019: contrato UID-wide, adaptador de billing e projeto iOS preservados |
